# Reproduction of Usman & Ali

This document records how the two models of *Plant Leaf Disease Detection Using Traditional CNN
and MobileNet Architecture* ([`paper.pdf`](paper.pdf)) were re-implemented. It lists what the
paper states, every assumption made where it is silent, and the results.

> **Status:** code done. Results appear in §5 only once real runs have produced them. They are
> generated by `python -m leafdx.train.report reproduction` from `ml/results/`.

## 1. What the paper states

| Item | Paper says | Where |
|---|---|---|
| Data | Kaggle "New Plant Diseases Dataset", 38 classes, 14 species, 80/20 split, 70,294 train / 17,572 validation (87,866 total) | §1–2, Table 2 |
| Input | 224 × 224 | Figures 2–3 |
| Augmentation | rotation up to 30°, brightness range, width/height shift, shear, zoom, horizontal and vertical flip | §2 |
| CNN | 3 × [Conv2D 32 filters 3×3 ReLU → MaxPool 2×2 → Dropout 20%] → Conv2D 128 3×3 ReLU → MaxPool 2×2 → Flatten → Dense 128 ReLU → Dense 64 ReLU → Dense 38 **sigmoid** | Figure 2, §3 |
| MobileNet | pretrained MobileNet base → GlobalAveragePooling → Dropout 0.2 → Dense 38 softmax | Figure 3, §3 |
| Training | 20 epochs, cross-entropy loss; "150 validations per epoch step", "validation was done after every 100 steps" | §4, §5 |
| Results | CNN 97.11% / 0.0898 (train) and 90.25% / 0.3605 (val); MobileNet 93.48% / 0.2060 (train) and 95.47% / 0.1419 (val) | Table 3 |
| Report | accuracy, macro and weighted average all 0.95, support 17,572 | Figures after §5.2 |

## 2. Assumptions

Ids are referenced from the config files (`ml/configs/paper/*.yaml`).

| Id | Assumption | Why | Alternative |
|---|---|---|---|
| A1 | **Loss = Keras `categorical_crossentropy`** for both models, including the sigmoid CNN. The metric is Keras' `"accuracy"`, which then means categorical accuracy. | The CNN curve (page 12) starts at loss 1.68 and accuracy 0.53 in epoch 1. With binary cross-entropy on 38 sigmoid outputs, the loss starts near 0.69 and per-element "accuracy" is above 0.97 from the first step (37 of 38 targets are 0), so BCE cannot have produced that curve. Keras' categorical cross-entropy renormalises the sigmoid outputs to sum to 1, so it trains. | The CNN run also logs `binary_accuracy`, to show what BCE-style accuracy would have reported. |
| A2 | Images resized with **nearest-neighbour** interpolation. | Default of Keras' `flow_from_directory`, the usual way this dataset is loaded. | bilinear |
| A3 | Pixels **rescaled to [0, 1]** (`rescale=1/255`) for both models. | Typical `ImageDataGenerator` usage. Note that ImageNet MobileNet weights expect [-1, 1]. | `data.preprocessing: mobilenet` |
| A4 | **Adam, learning rate 1e-3, batch size 32.** | Keras defaults and the `flow_from_directory` default batch size. The paper names none of these. | |
| A5 | Augmentation values: width/height shift 0.2, shear 0.2°, zoom 0.2, brightness [0.8, 1.2], fill `nearest`. Augmentation is applied to training images only. | Common tutorial values; only "up to 30°" rotation is given. | |
| A6 | **MobileNet backbone frozen**; only the new head (38,950 parameters) trains. | §6 Conclusion: transfer learning "saved our time instead of training our whole model like we did for CNN". Also, train accuracy stays *below* validation accuracy for all 20 epochs (page 11), which fits a frozen base plus dropout and augmentation. | `model.freeze_backbone: false` |
| A7 | MobileNet V1, width multiplier α = 1.0, ImageNet weights. | "MobileNet" with a citation of Howard et al. (2017). | |
| A8 | **Two readings of the schedule are run.** (a) `steps_per_epoch=100`, `validation_steps=150`, i.e. 3,200 training images per "epoch" and validation on 150 random batches; (b) full passes over the data. | §4's wording ("150 validations per epoch step", "validation was done after every 100 steps") matches the Keras `fit` arguments in (a). The MobileNet curve also supports (a): train accuracy 0.48 in epoch 1 is low for a full pass over 70k images. Since this is not certain, both are reported. | |
| A9 | Seed 42, single run per configuration. | The paper reports a single run. Phase 3 uses 3 seeds. | |

**Keras 3 note.** `ImageDataGenerator` was removed in Keras 3. Its parameters are mapped to
preprocessing layers in `leafdx.train.data.build_augmentation`:

| ImageDataGenerator | Keras 3 layer |
|---|---|
| `rotation_range` (degrees) | `RandomRotation(deg/360)` |
| `width_shift_range`, `height_shift_range` | `RandomTranslation` (same fractions) |
| `shear_range` (degrees) | `RandomShear(tan(deg))` |
| `zoom_range` | `RandomZoom`, independent ±z on each axis |
| flips | `RandomFlip` |
| `brightness_range` (multiplicative) | a small custom layer |

The order of operations and the random sampling details differ slightly from
`ImageDataGenerator`.

## 3. Inconsistencies in the paper

1. Table 2 gives 70,294 train images, but the Kaggle dataset (version 2) has **70,295**. The
   validation count (17,572) matches.
2. The text gives the CNN's test loss as 0.1419 (§5.1), which is MobileNet's figure. Table 3
   gives **0.3605**. This reproduction compares against Table 3.
3. The MobileNet accuracy plot (page 11) extends past epoch 20, while the text says 20 epochs.
4. The CNN's sigmoid output is described as "for multi-label classification", but the task is
   single-label (one disease per image). See A1.
5. §Methodology mentions "three different" CNN models, but only two are described. Figure 4 is
   captioned "AlexNet Architecture", but no AlexNet appears in the paper.
6. The classification report (accuracy 0.95, support 17,572) is not labelled with a model. Its
   numbers match MobileNet, so it is compared with MobileNet here.

## 4. How to run

```bash
cd ml
make setup && .venv/bin/pip install -e ".[train]"   # local; needs Python 3.10–3.12
python -m leafdx.train.run --config configs/paper/cnn_steps100.yaml
python -m leafdx.train.report collect outputs
python -m leafdx.train.report reproduction          # -> docs/figures/reproduction/
```

On a free Kaggle GPU, use `ml/notebooks/kaggle_train.ipynb` (instructions inside). Each run
records its library versions, device and git commit in `env.json`.
